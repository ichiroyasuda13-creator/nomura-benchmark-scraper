1このアプリは何をするもの？

ひとことで言うと：野村アセットマネジメントの投資信託について、「その商品がどの指数（ベンチマーク）を使っているか」を、公式PDF（交付目論見書）から自動で読み取って、一覧表（Excel/CSV）にするアプリです。

なぜ必要か：MSCIの営業では、「純資産（AUM）が大きいのに、まだMSCI以外の指数を使っているファンド」を見つけることが重要です。数百本のファンドのPDFを人が1本ずつ開いて確認するのは大変なので、その作業を自動化します。

何が出てくるか：ファンド名・純資産・ベンチマーク指数・指数の提供会社（MSCI / TOPIX / 日経 など）・MSCI採用かどうか、が並んだ表が出力されます。この表を見れば、営業でどこを攻めるべきかが一目でわかります。

【入力】野村の公式サイト（AUM上位100本） ↓ 自動でPDFを取得して読み取り 【出力】Excel/CSV の一覧表 ┌──────────┬────────┬──────────────┬──────────┬────────┐ │ ファンド名 │ 純資産 │ ベンチマーク │ 提供会社 │ MSCI？ │ ├──────────┼────────┼──────────────┼──────────┼────────┤ │ ○○ファンド │ 1兆円 │ MSCIコクサイ │ MSCI │ はい │ │ △△ETF │ 3兆円 │ TOPIX │ 東証 │ いいえ │ ← 攻めどころ └──────────┴────────┴──────────────┴──────────┴────────┘

2アプリの処理の流れ

技術がわからなくても、この6段階だけ知っておけば十分です。

一覧を取る：公式サイトから、純資産の大きい順に上位100本のファンド名を取得
PDFの場所を探す：各ファンドの詳細ページから「交付目論見書」PDFのURLを取得
PDFを保存：そのPDFをダウンロード
文字にする：PDFから文章を取り出す（画像の場合はOCRで読み取る）
指数を読み取る：文章から「○○に連動」「○○をベンチマーク」を見つけて指数名を特定
表にする：Excel/CSVに整形して出力
💡 途中で失敗しても大丈夫：成功した段階までは保存されるので、もう一度実行すれば続きから再開できます。

3動かす前に用意するもの

実際にアプリを動かす担当者向けです。営業・企画の方はここは読み飛ばしてOKです。

  • Python 3.11 以上
  • 必要な部品（ライブラリ）：requirements.txt に記載（Playwright, PyMuPDF, pytesseract, pandas など）
  • OCR用ソフト：Tesseract（日本語データ jpn）と poppler
  • Anthropic APIキー：指数の読み取りにAIを使用。環境変数 ANTHROPIC_API_KEY に設定
  • インターネット接続：野村サイトへのアクセスに必要
⚠️ 注意：APIキーはコードに直接書かず、必ず環境変数か .env ファイルに入れてください（社外に漏らさないため）。

4セットアップ手順（初回だけ）

# 1. プロジェクトのフォルダに移動
cd nomura-benchmark-scraper

# 2. 必要な部品をインストール
pip install -r requirements.txt

# 3. ブラウザ部品を入れる（Playwrightを使う場合）
playwright install chromium

# 4. APIキーを設定（.env.example をコピーして .env を作り、キーを記入）
cp .env.example .env
#   .env を開いて ANTHROPIC_API_KEY=... を記入

Tesseract と poppler は OS ごとに入れ方が異なります（例：Mac は brew install tesseract tesseract-lang poppler）。詳細は README.md を参照してください。

5基本の使い方

いちばん簡単な方法（全部いっぺんに）

python -m app.run

これだけで「一覧取得 → PDF取得 → 文字化 → 指数抽出 → 表出力」まで通しで実行され、最後に output/nomura_benchmarks.xlsx と .csv ができます。

段階ごとに実行したいとき（デバッグや部分的なやり直し）

python -m app.stage1_list          # 一覧だけ取得
python -m app.stage2_pdf_url       # PDFのURLだけ取得
python -m app.stage3_download      # PDFのダウンロードだけ
python -m app.stage4_extract_text  # 文字化だけ
python -m app.stage5_benchmark     # 指数の読み取りだけ
python -m app.stage6_output        # 表の出力だけ
💡 本数を変えたいとき：上位100本ではなく50本にしたい等は設定ファイル（または起動時オプション）で指定します。実装に合わせて README.md の「設定」欄を確認してください。

6出力ファイル（表）の見方

output/nomura_benchmarks.xlsx の主な列と、営業での使い方です。

列名意味営業での見方
rank純資産の順位上位ほど影響が大きい
fund_nameファンド名—
aum純資産総額大きいほど重要顧客
fund_typeインデックス型／アクティブ型／バランス型 など—
benchmark使っている指数の名前—
index_provider指数の提供会社（MSCI/東証/日経/野村など）—
is_msciMSCIの指数を使っているか（はい/いいえ）営業判断の中心。「いいえ」で純資産が大きい＝置換提案の狙い目
confidence読み取りの確からしさ（high/medium/low）low は要確認
needs_review人の目で確認したほうがよい行の印「はい」の行は営業に使う前にチェック
prospectus_pdf_url根拠にしたPDFのURL確認したいときに開く
note補足・不明の理由など—
💡 使い方のコツ：is_msci = いいえ かつ aum が大きい行を上から見ていくと、「MSCIに乗り換えてもらう価値が高いファンド」が並びます。ただし needs_review = はい の行は、営業に使う前に必ず根拠PDFで確認してください。

7うまくいかないとき

「ベンチマークが不明」の行が多い

いちばん多い症状です。原因は主に2つで、切り分け方は簡単です。まず、不明になったファンドの文字化ファイル（data/text/{ファンドコード}.txt）を開き、指数名（MSCI、TOPIX、日経 など）が文章の中にあるか探します。

確認結果原因対策
指数名が文章の中にあるのに不明読み取りルールの問題改善版ドキュメント §2・§3（トリガー語の拡張と指数名の切り出し）
指数名が文章の中にない文字化け・OCRの問題改善版ドキュメント §5（OCRの強制）
最大の改善策：インデックスファンドは「ベンチマーク」という言葉を使わず「○○に連動する投資成果をめざします」と書きます。読み取り条件を「連動」系まで広げるのが最も効果的です。

PDFがダウンロードできない／URLが違う

野村のPDFのURLの作り方が変わった可能性があります。ファンド詳細ページを開き、「交付目論見書」リンクの本当のURLを確認して、Stage 2 の取得方法を合わせます。

サイトから一覧が取れない

野村の検索ページはページを開いた後に中身が表示される仕組みです。ページの裏で動いているデータ取得の通信（API）を調べると安定します。仕様書 §4（最優先の調査タスク）を参照してください。

8他の運用会社・ファンドに応用する

このアプリは「野村専用」の部分と「どの運用会社でも使い回せる」部分に分かれています。応用のコツは、使い回せる部分はそのまま、会社ごとに違う部分だけ作り替えることです。

作り替えが必要

会社ごとに違う部分

  • 一覧の取り方（Stage 1）
  • PDFの場所の探し方（Stage 2）
そのまま使える

どの会社でも共通

  • PDFの文字化・OCR（Stage 4）
  • 指数の読み取りロジック（Stage 5）
  • 表の出力（Stage 6）
💡 要点：大和アセットや三菱UFJアセットに広げる場合も、指数を読み取る心臓部（Stage 4〜6）はほぼ流用でき、サイトからの取得（Stage 1〜2）だけ作り直せばよいのが基本です。

8-2. Cursor への指示の出し方

Cursor には「実際のコードを書く・直す」ことを頼みます。仕様書と改善版ドキュメントをプロジェクトに置いた状態で、以下のように指示します。

💻 テンプレD：新しい運用会社に対応させる
このリポジトリは野村アセット向けのファンド・ベンチマーク抽出アプリです。
仕様は nomura_benchmark_scraper_spec.md、抽出改善は
benchmark_extraction_improvement.md にあります。

これを「大和アセットマネジメント」に対応させてください。
1. Stage 4〜6（テキスト抽出・ベンチマーク抽出・出力）は原則そのまま流用。
2. Stage 1（一覧取得）を大和アセットのファンド検索ページ用に作り直す。
   ・まずブラウザのDevToolsでデータ取得APIがないか調べ、あればそれを使う。
   ・対象URL: <URLを貼る>
   ・純資産の降順で上位100本を funds.json に出す。
3. Stage 2（交付目論見書PDFのURL取得）を大和向けに作り直す。
   ・詳細ページのHTMLから「交付目論見書」リンクを厳密に判定して取得。
4. 会社ごとの違いは設定ファイル(config)に切り出し、
   1つのコードベースで会社を切り替えられる構造にリファクタしてください。
出力の列は野村版と同じスキーマを維持すること。
💻 テンプレE：抽出の不明を減らす改修
benchmark_extraction_improvement.md の方針に沿って、Stage 5 を改修してください。
特に：
・トリガー語を「連動する投資成果をめざす」「対象インデックス」等まで拡張（§2）
・指数名の括弧修飾（配当込み等）を落とさない切り出し（§3）
・ファンド名からのフォールバック抽出を追加（§4）
・インデックス型で本文から取れない場合はOCRを強制（§5）
改修後、§9のテストケースが「不明」にならないことを確認してください。
💻 テンプレF：まず小さく試す
いきなり100本ではなく、まず上位5本だけで通しで動かせるようにしてください。
各Stageの結果（funds.json、PDF、text、抽出結果）を確認できるログを出し、
5本が正しく取れることを確認してから本数を増やせる作りにしてください。
💡 コツ：Cursor には一度に全部ではなく、Stageごと・少数本から頼むと失敗が減ります。仕様書と改善版をリポジトリに入れて「これに従って」と指示するのが最も確実です。

9用語集

AUM（純資産総額）そのファンドに集まっているお金の総額。大きいほど影響力・重要度が高い。
ベンチマーク／指数ファンドが目標や基準にする「ものさし」。例：TOPIX、日経225、MSCIコクサイ。
インデックス型（パッシブ）指数と同じ値動きをめざすファンド。「○○に連動」と書かれる。
アクティブ型指数を上回ることをめざすファンド。「○○をベンチマークとする」等。
交付目論見書投資信託の公式な説明書（PDF）。ベンチマークはここに書かれている。
OCR画像になっている文字を読み取って文章に変換する技術。
APIプログラム同士がデータをやり取りする窓口。サイトの裏側でデータを返していることがある。
指数プロバイダー指数を作って提供している会社。MSCI、東証（JPX）、日経、野村など。
confidence（確からしさ）自動読み取りの信頼度。low は人の確認推奨。
needs_review人の目で確認したほうがよい、という印。
🆘 困ったときは
  • 設計や調査、結果の整理 → Claude（このチャット）に、関連ファイルを添付して相談
  • 実際のコードの作成・修正 → Cursor に、仕様書と改善版を渡して依頼
  • 不明が多いなど品質の問題 → まず data/text/ を確認し、改善版ドキュメント §10（デバッグの勘所）へ
